## **1. 项目概述**

### **1.1. 项目背景**

本项目是"云腾动力数智技术工作室"的核心能力演示项目之一，旨在向潜在客户（尤其是电商、贸易及拥有多线上渠道的企业）直观展示RPA（机器人流程自动化）技术的应用价值。当前，许多企业员工需要手动登录多个独立的电商或订单平台，逐个复制、粘贴订单信息，最后合并到一张Excel发货单中。此过程不仅耗时巨大、枯燥重复，而且极易因人为疏忽导致数据错漏，影响发货效率与客户满意度。

### **1.2. 项目目标**

本演示项目的核心目标并非解决某一具体客户的业务量，而是**产品化地展示技术能力**，达成以下效果：

* **价值具象化:** 将"效率提升"和"降低错误率"这两个核心价值点，通过一个看得见、摸得着的自动化流程生动地呈现出来。
* **缩短沟通成本:** 用一个极致简单的成功案例，快速与潜在客户建立对话基础，证明我们有能力解决其业务流程中的痛点。
* **可量化演示:** 演示在无人干预的情况下，将原先可能需要15-30分钟的手动操作，在1分钟内自动完成。

## **2. 流程分析**

### **2.1. 现有流程 (As-Is)**

(此流程为模拟的通用手动操作流程)

**涉及系统:** 电商平台A (如淘宝/天猫)、电商平台B (如京东/拼多多)、Microsoft Excel

**流程步骤:**

1. 员工手动打开浏览器，登录电商平台A的后台管理系统。
2. 导航至"已付款订单"页面，筛选出当日待发货订单。
3. 手动复制每笔订单的关键信息（如订单号、收件人、电话、地址、商品信息等）。
4. 打开一个预设的Excel发货单模板。
5. 将从平台A复制的信息，逐条粘贴到Excel表格的对应列中。
6. 员工再次手动打开新的浏览器标签页，登录电商平台B的后台管理系统。
7. 重复步骤2和3，获取平台B的待发货订单信息。
8. 将从平台B复制的信息，继续粘贴到同一张Excel表格中。
9. 由于不同平台的字段名称和格式可能存在差异，员工需要手动调整、统一数据格式（例如，将"买家昵称"和"客户名"统一为"收件人姓名"）。
10. 保存最终的Excel发货单，并准备打印。

### **2.2. 目标流程 (To-Be)**

(此流程为RPA机器人介入后的理想流程)

**触发方式:** 手动点击运行机器人程序（用于演示目的）。

**流程步骤:**

1. 机器人从配置文件中读取需要处理的电商平台列表及登录凭据。
2. 机器人自动打开浏览器，静默登录电商平台A。
3. 机器人自动导航至订单页面，抓取所有待发货订单的数据。
4. 机器人自动登录电商平台B，重复步骤3。
5. 机器人将从两个平台抓取的数据，在内存中进行清洗和标准化，统一映射到标准发货单字段。
6. 机器人根据标准格式，生成一个全新的Excel文件。
7. 机器人将所有处理好的订单数据一次性写入该Excel文件。
8. 机器人将文件以`合并发货单_YYYYMMDD_HHMMSS.xlsx`的格式保存到指定的输出文件夹中。
9. 机器人在控制台输出"流程执行成功"的消息，并告知文件生成路径。

## **3. 需求详述**

### **3.1. 自动化范围**

* **范围内 (In Scope):**
  * 自动登录2个**模拟的**Web电商平台。
  * 自动抓取订单列表页面的结构化数据。
  * 对抓取的数据进行标准化处理。
  * 将合并后的数据生成一个结构统一的Excel文件。
* **范围外 (Out of Scope):**
  * 处理登录过程中的验证码或双因素认证。
  * 处理真实的、需要付费的电商平台接口。
  * 订单的自动发货、付款状态同步等操作。
  * 处理超过2个以上的平台。
  * 7x24小时无人值守运行（本项目为手动触发演示）。

### **3.2. 功能性需求**

#### **3.2.1. 数据输入**

| 输入项 | 来源/路径 | 格式/命名规则 | 备注 |
| :---- | :---- | :---- | :---- |
| 平台凭据 | 环境变量文件 (.env) | PLATFORM_A_USER, PLATFORM_A_PASS 等 | 存储各平台登录的用户名和密码。 |
| 平台配置 | 配置文件 (config.yml) | N/A | 存储各平台的登录网址、界面元素选择器等。 |

#### **3.2.2. 处理逻辑**

* **登录逻辑:** 机器人将根据config.yml中的URL和选择器信息，结合.env中的凭据，完成平台登录。
* **数据抓取逻辑:** 机器人将抓取订单表格中的每一行，并提取指定的列数据。
* **数据映射逻辑:** 机器人需内置一个映射规则，将不同平台的字段名统一为标准字段名。示例如下：

| 平台来源 | 原始字段名 | 标准字段名 |
| :----| :---- | :---- |
| 平台A | 买家昵称 | 收件人姓名 |
| 平台B | 收货人 | 收件人姓名 |
| 平台A | 收货地址 | 收货地址 |
| 平台B | 详细地址 | 收货地址 |

* **数据合并逻辑:** 将来自所有平台的数据合并到一个数据结构中，并增加一列"平台来源"以作区分。

#### **3.2.3. 数据输出**

| 输出项 | 目标/路径 | 格式/命名规则 | 备注 |
| :---- | :---- | :---- | :---- |
| 合并发货单 | data/output/ | `合并发货单_YYYYMMDD_HHMMSS.xlsx` | 报告需包含标准列：订单号, 平台来源, 收件人姓名, 联系电话, 收货地址, 商品名称, 数量, 下单时间。 |
| 运行日志 | logs/ | `rpa_process.log` | 记录流程的关键执行步骤、成功信息和任何错误。 |
| 失败截图 | data/output/ | `error_screenshot_YYYYMMDDHHMMSS.png` | 当发生无法处理的异常时，自动截取当前屏幕。 |
| 失败邮件 | (本次演示不涉及) | N/A |  |

### **3.3. 非功能性需求**

* **运行计划:** 手动触发执行。
* **性能要求:** 整个演示流程在正常网络环境下，应在1分钟内完成。
* **可靠性与异常处理:**
  * **平台登录失败:** 机器人应尝试重新登录，共2次，每次间隔5秒。若仍失败，则记录错误日志、截取屏幕，并终止流程，在控制台打印明确的失败原因。
  * **未找到订单数据:** 如果登录后未发现任何待处理订单，机器人应记录正常日志，并生成一个空的但表头完整的Excel文件，流程正常结束。
  * **未找到UI元素:** 在操作过程中，若关键的界面元素（如"下一页"按钮）未找到，流程应记录错误日志、截图并终止。
* **安全性:**
  * 所有密码、密钥等敏感信息严禁硬编码在代码或配置文件中，必须通过环境变量文件加载。
  * .env文件本身不提交到版本控制系统（Git）。

## **4. 验收标准**

(定义清晰、可测试的验收条件。当所有条件都满足时，项目才算成功交付。)

1. 机器人程序可以双击或通过命令行成功启动，无报错。
2. 机器人能成功使用配置文件中的信息，自动登录两个模拟的电商平台。
3. 机器人能准确抓取两个平台上所有模拟的订单数据。
4. 最终在data/output/目录下，能找到一个根据`合并发货单_YYYYMMDD_HHMMSS.xlsx`规则命名的Excel文件。
5. 打开生成的Excel文件，其表头与3.2.3中定义的标准列完全一致。
6. 文件内容包含了来自两个平台的所有订单，且"平台来源"列已正确标记。
7. 文件中的"收件人姓名"、"收货地址"等字段，已根据3.2.2中的映射规则完成统一。
8. 当故意在.env中设置错误的密码时，机器人运行后不会卡死，而是会在尝试2次后终止，并在日志文件中记录"登录失败"的错误信息。
9. 当某个平台的订单列表为空时，机器人仍能正常完成流程，最终生成的Excel文件中仅包含另一个平台的订单数据。
